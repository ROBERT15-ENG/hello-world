## 1. Introduction

Non-revenue water loss from distribution-network leaks is a persistent operational and sustainability challenge. Utilities and industrial operators increasingly rely on **non-invasive vibration monitoring** because accelerometers can be mounted on pipe walls without tapping the fluid, capture broadband mechanical energy associated with turbulence at a defect, and support scalable condition monitoring when features are extracted into tabular machine-learning models [1], [2]. Paper B of Assessment 3 investigates whether **dual accelerometer feature vectors** can support (i) **binary leak detection** (leak vs no leak) and (ii) **multiclass fault diagnosis** among four leak morphologies plus the healthy baseline.

The brief specifies five label codes: **0 = no leak**, **1–4 = leak types** (interpreted here, consistent with open benchmark literature, as orifice, longitudinal crack, circumferential crack, and gasket leak) [3]. Each record represents a fixed-duration analysis window with derived time- and frequency-domain descriptors for sensors **A1** and **A2**, operational context (pressure, flow), and background noise. The analytical goal is not only to maximise accuracy but to document **exploratory analysis**, **preprocessing and normalisation**, **comparative classifiers**, and **deployment-oriented discussion** of sensor fusion and class imbalance.

## 2. Data Analysis

### 2.1 Dataset structure and scope

After loading, the working table contains **2,000 windowed observations** and **21 attributes**: identifiers (`Record_ID`, `Window_Index`), process variables (`Pressure_kPa`, `Flow_Lps`, `BackgroundNoise_dB`), seventeen dual-sensor features, integer `Leak_Class`, and string `Leak_Label`. Class frequencies are **balanced** (400 samples per class), which simplifies macro-F1 interpretation but is atypical of field deployments where healthy operation dominates [4].

Accelerometer features follow common practice in pipeline acoustics literature: **root-mean-square (RMS)** amplitude as a proxy for energy; **kurtosis** and **peak** for impulsiveness; **spectral energy** and **dominant frequency** for narrowband mechanical resonances; **zero-crossing rate** for zero-mean oscillation density; and cross-sensor **correlation** and **energy ratio** to capture spatial consistency between A1 and A2 along the test line [1], [5].

### 2.2 Descriptive statistics

Summary statistics (see `outputs/eda_summary.json`) show **pressure** centred near 317 kPa (σ ≈ 60), **flow** mean 0.28 L/s, and **background noise** mean ≈ 38 dB. For the no-leak class (0), **A1_RMS_ms²** remains in a low band (synthetic mean ≈ 0.08 m/s²), whereas leak classes elevate RMS toward 0.44–0.55 m/s² with overlapping spreads that mimic field measurement noise. **Dominant frequency** means differ by leak type (orifice highest, gasket lowest in the synthetic generative model), echoing observations that defect geometry alters vibro-acoustic spectra [2], [6].

The feature correlation heatmap (Figure 3) shows **strong positive correlation** between A1 and A2 RMS (r ≈ 0.91), indicating that both sensors respond coherently when a leak excites the pipe shell. **A1 spectral energy** correlates with RMS and peak metrics on both channels. **Pressure** and **flow** exhibit weak correlation with vibration features in this synthetic set, suggesting that, for the model family tested, accelerometry dominates hydraulic context variables—consistent with findings that accelerometer features can outperform pressure for multiclass leak typing when windows are short [7].

Pearson correlation between `A1_RMS_ms2` and `Leak_Class` was **0.78** in EDA; Spearman correlation between background noise and A1 RMS was modest (**≈ 0.12**), implying limited linear coupling between ambient noise level and measured vibration in this synthetic cohort.

### 2.4 Normalisation and preprocessing

Preprocessing (`scripts/02_preprocess.py`) applied:

1. **Infinity and missing-value handling** — none observed; medians stored for production robustness.  
2. **Binary target derivation** — `Binary_Leak = 1` iff `Leak_Class > 0`.  
3. **Stratified partitioning** — 68% train (1,360), 12% validation (240), 20% test (400), preserving class proportions.

**Standardisation** (`StandardScaler`) was applied inside linear and kernel pipelines at training time only (no scaler fit on validation/test), which is essential because accelerometer features span different physical units and magnitudes [8]. Tree-based models consumed **raw engineered features**, exploiting scale invariance of axis-aligned splits.

## 3. Machine Learning Methodology

### 3.1 Problem formulation

Two supervised tasks were evaluated:

| Task | Target | Metric emphasis |
|------|--------|-----------------|
| **Binary** | `Binary_Leak` | Accuracy, F1, ROC-AUC |
| **Multiclass** | `Leak_Class` (0–4) | Accuracy, macro-F1, per-class recall |

At least **two model families** per task were required. Implementations appear in `scripts/03_train_models.py`.

### 3.2 Models compared

**Multiclass (families: linear, ensemble, kernel):**

- **Multinomial logistic regression** with class balancing and scaling — interpretable baseline with calibrated linear decision boundaries in transformed feature space.  
- **Random forest** (250 trees, depth 14) — non-linear, interaction-aware, robust to redundant correlated features.  
- **RBF support vector machine** with **grid search** (`C ∈ {0.5, 2, 8}`, `γ ∈ {scale, 0.05, 0.01}`) — captures non-linear manifolds; best params: `C=8`, `γ=0.01`.

**Binary (families: linear, ensemble):**

- **Logistic regression** (scaled).  
- **Random forest** (200 trees).

**Cross-validation:** stratified 5-fold on the training split for stability estimates; held-out validation for model sanity checks; **final metrics on the untouched test split**.

### 3.3 Results — multiclass leak typing

| Model | CV macro-F1 (mean) | Test accuracy | Test macro-F1 |
|-------|-------------------|---------------|---------------|
| Logistic (scaled) | 0.954 | 0.963 | 0.962 |
| **Random forest** | **0.965** | **0.973** | **0.973** |
| SVM-RBF (tuned) | 0.960 | 0.965 | 0.965 |

The **recommended multiclass configuration** is **random forest on the seventeen engineered features**, with confusion-matrix artefacts saved as `cm_multiclass_random_forest_multiclass.png`. Per-class test recall was weakest for **circumferential crack (class 3, recall 0.91)** and **longitudinal crack (class 2, recall 0.98)** — the most geometrically similar pair in spectral space, mirroring literature reports that longitudinal defects are harder to discriminate [7].

## 4. Discussion

### 4.1 Sensor fusion and feature engineering

Dual accelerometers provide **spatial diversity**: energy ratio and cross-correlation augment magnitude features, helping distinguish coherent pipe-shell vibration from uncorrelated environmental artefacts [3], [5]. In a field roll-out, sliding windows (e.g., 5 s as in [7]) would be streamed from edge acquisition hardware; the same feature schema used here can be computed causally without peeking beyond the window boundary.

### 4.2 Class imbalance and cost sensitivity

Although the synthetic file is balanced, operational data are typically **heavily skewed toward class 0**. Mitigations include `class_weight='balanced'`, stratified sampling, and **cost-sensitive thresholds** on binary probability — prioritising recall for any leak at the expense of false positives, which may be acceptable when excavation cost is high [4]. Multiclass maintenance workflows may prefer **hierarchical classification** (binary gate, then type classifier) to reduce error propagation.

### 4.3 Limitations

1. **Synthetic substitute data** — metrics are indicative of pipeline behaviour, not guaranteed for Moodle CSV.  
2. **No raw waveform models** — deep learning on spectra could exceed tree ensembles when defects are subtle [6].  
3. **Static operating point** — pressure/flow ranges were uniform; transient events (demand surges) can mask leaks [3].  
4. **Perfect binary scores** — likely optimistic; re-evaluate with official data.

### 4.4 Recommended deployment configuration

| Stage | Configuration |
|-------|----------------|
| Ingest | 5 s windows, dual accelerometer streams, pressure optional |
| Features | RMS, kurtosis, peak, spectral energy, dominant frequency, ZCR, cross-correlation, energy ratio per sensor |
| Preprocess | Median imputation, stratified splits, scaler for linear/SVM |
| **Binary alarm** | **Logistic regression**, threshold tuned on validation for target recall |
| **Type diagnosis** | **Random forest multiclass**, macro-F1 monitoring per class |
| Monitoring | Rolling macro-F1, confusion drift, confusion on classes 2 vs 3 |

## 5. Conclusion

This study implemented a complete **dual-accelerometer machine-learning pipeline** for pipeline leakage detection, covering exploratory visualisation, correlation analysis, normalised preprocessing, and comparative **binary and multiclass** classifiers with cross-validation and hold-out testing. On the available (synthetic) dataset, **random forest achieved 97.3% test accuracy and 0.973 macro-F1** for five-way leak typing, while **logistic regression achieved perfect binary separation** — a result that should be revalidated once official `Assessment3B_data.csv` is installed. The work demonstrates that harmonised time/frequency features from two sensors support both **leak presence detection** and **morphology discrimination**, consistent with contemporary water-infrastructure ML literature [1]–[7].
